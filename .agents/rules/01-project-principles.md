# Rule 01: Project Principles

## Purpose
This rule establishes the foundational identity, operating philosophy, and core principles governing all development and design on the Mahābhārata Explorer project.

---

## 1. Core Principles

1. **Interconnected Knowledge Explorer**: Mahābhārata Explorer is a modern digital atlas and interconnected knowledge explorer. It is not a static blog, encyclopedia, family-tree widget, timeline page, or open-world game.
2. **One Knowledge Graph, Many Lenses**: The product is built on **ONE shared Knowledge Graph** explored through **MANY lenses** (Time, Space, People, Relationships, Events, and Evidence). All lenses query the same unified graph.
3. **Information is the Hero**: Visual elegance and thematic styling must support comprehension and never overwhelm the information architecture.
4. **Connected Exploration (No Dead Ends)**: Users should be able to enter through any meaningful entity (person, event, place, relationship, war day, or source) and seamlessly navigate into connected knowledge.
5. **Evidence & Provenance are Fundamental**: Factual assertions must connect to supporting evidence and identifiable sources through the `Entity → Claim → Evidence → Source` model.
6. **Data Drives Presentation**: The user interface renders based on structured data. Missing data must never be filled with fabricated content or speculative visuals.
7. **Progressive Disclosure**: Complexity must be managed through progressive disclosure (overview first, zoom/filter, details on demand).
8. **Accessibility is Foundational**: Accessible navigation, semantic elements, keyboard support, screen-reader compatibility, and sufficient contrast are mandatory first-class requirements.
9. **Responsive by Design**: Responsive behavior across desktop and mobile form factors is a core requirement, adapting interaction models rather than simply scaling layouts.
10. **Modern First, Traditional Second**: The product is an excellent modern information product first, embedding Mahābhārata and Indic visual motifs intelligently with semantic purpose.

---

## 2. Rule Priority & Conflict Resolution

1. **Human Instruction**: Explicit instructions provided by the user for the current task take immediate precedence.
2. **Domain Documentation**: Approved project documents govern their respective domains as defined in `docs/00-documentation-context.md`.
3. **Persistent Rules**: These agent rules govern development behavior, constraints, and quality standards.
4. **Technical Specifications**: Once formally authored and approved in subsequent stages, technical specifications become authoritative for their implementation domains.
5. **Conflict Escalation**: If an unresolvable conflict or ambiguity is discovered, agents must **STOP and request human clarification** rather than making unilateral assumptions.
